# 화면 3 스펙: 대용량 가상 스크롤 (Virtual Scroll)

## 1. 개요 및 목적
* **화면 ID**: `virtual` / 화면 번호 `03`
* **목적**: 1만 건, 10만 건, 그리고 최대 **100만 건(1,000,000건)**의 엔터프라이즈 빅데이터를 브라우저 메모리 부하 없이 60fps로 매끄럽게 처리하는 타키온의 고성능 가상 스크롤(Virtual Scrolling) 렌더링 엔진을 시연합니다.
* **제안 슬라이드 매핑**: [슬라이드 1] 대용량 데이터와 가상 스크롤 (타키온 3대 핵심 가치 중 첫 번째)

## 3. 필수 UI 구성요소 및 성능 지표 패널

### A. 실시간 성능 측정 대시보드 (KPI 칩)
| 지표명 | 계산 방식 및 표시 내용 | 시연 가치 |
| :--- | :--- | :--- |
| **전체 데이터 건수** | 현재 로드된 건수 (`10,000건`, `100,000건`, `1,000,000건`) | 대용량 데이터 수용력 증명 |
| **화면 가상 셀 수** | 현재 뷰포트에 실제 DOM/Canvas로 그려진 셀 수 (예: `약 180개`) | 100만 건이어도 화면에 보이는 셀만 렌더링함을 입증 |
| **데이터 생성 시간** | 인메모리 루프 생성 시간 (ms 단위) | 프론트엔드 연산 효율성 |
| **첫 렌더링 소요 시간** | 데이터 바인딩 후 그리드가 첫 프레임을 완성하기까지의 시간 (ms) | 압도적인 초기 진입 속도 |
| **실시간 렌더링 FPS** | `requestAnimationFrame` 기반 뷰포트 스크롤 프레임 레이트 (목표 `60 FPS`) | 버벅임 없는 극강의 부드러움 증명 |

### B. 데이터 건수 전환 컨트롤러
* 버튼 그룹: **[1만 건]** | **[10만 건]** | **[100만 건]**
* 건수 선택 시 비동기 웹 작업으로 전환되며 로딩 스피너 및 즉시 갱신.

## 4. 핵심 시연 포인트 및 인터랙션 시나리오
1. **100만 건 초고속 스크롤**:
   * 스크롤바를 맨 위에서 맨 아래까지 급격히 드래그해도 화면 멈춤(Freezing)이나 메모리 누수 없이 60fps 렌더링 유지.
2. **뷰포트 기반 가상화 메커니즘 시각화**:
   * "데이터는 100만 건이지만 브라우저가 실제로 그리는 셀은 뷰포트 영역인 180여 개에 불과하다"는 점을 수치로 명확히 입증.
3. **대용량 상태에서의 정렬 및 필터**:
   * 100만 건 대용량 상태에서도 헤더 클릭 시 빠른 정렬 수행.
